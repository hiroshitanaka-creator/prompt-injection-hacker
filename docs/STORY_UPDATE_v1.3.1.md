# v1.3.1 STORY 更新仕様（ネタバレなし）

## 要求と変更権限

ユーザーの承認対象は、主人公がハッカーをする動機、NODEとの関係、導入、エピローグの考案と実装。具体的な物語はプレイまで公開しない。
NODEの確定人格、既存4ステージ、ヒント、防御解析、3難易度、スコア、段階的ロードマップは変更しない。
新ステージ追加ではないので、版番号はv1.3.1とする。

## 導線

起動 → タイトル → 序章 → 任務前会話 → 既存ステージ → 突破結果 → 任務後会話。
最終任務の報告後は、既存エピローグを拡充した物語へつなぐ。結果画面を逃しても「進行 → エピローグを読む」から再生できる。
既存セーブを消して最初からやり直すことを条件にしない。

物語記録は序章1、任務前4、任務後4、エピローグ1の計10記録。会話の選択は台詞にのみ影響。
序章からのキャンペーン再生はLv.1へ移動するが、攻略済み・ベストスコア・難易度・Trustを初期化しない。
アーカイブ再生はステージを移動しない。

## システム分離

- `js/story-data.js`：序章・任務前後の会話データ。確定ゲーム状態を変更するコードを持たない。
- `js/epilogue.js`：既存の結末・予告・未接続表示を維持した拡張データ。既存`getSteps()`を維持。
- `js/story.js`：ネイティブdialog、ページ送り、選択、既読、未解放判定、保存、再生コールバック。
- `css/story.css`：既存配色を継承する追加レイヤー。主画面の基本CSSはそのまま。
- `js/app.js`：ゲーム状態の唯一の更新主体を維持。storyへ渡すのは公開進行のみ。
- `js/companion.js`：ローカル会話。物語は既読フラグに応じて応答し、未読の具体内容を先出ししない。

NODEへ渡す情報：公開ミッション、試行数、警戒、ヒント使用数、検出手法、解放済み解析、直近の公開観測分類、クリア数、既読の物語フラグ。
渡さない情報：非公開の解法条件、正解文字列、非公開システムプロンプト、未解放ヒント、未読の物語本文。
ただし、静的サイトのクライアントコードをユーザーから秘匿する防壁ではない。将来のLLM接続ではサーバー側の境界を別途検証する。

## NODE応答の補正

自動発言で「ACCEPTだから防御内部へ入った」と断定せず、受理・拒絶の分類と情報漏えいの成立を分ける。
ルール、スコア、難易度、保存、人物会話、休憩、未知の質問を別経路にする。
勝手な無料攻略回答は加えず、方向・カテゴリ・具体文は従来のH1/H2/H3へ案内する。
会話と選択によるスコア減点・Trust変更を追加しない。既存のTrust増分は全条件で一致を検査。

## 保存

従来キーはそのまま。物語は別キー、schema version=1。保持項目はread、positions、choices、active。
読み込みはID・数値・選択値を検証し、未知フィールドを適用しない。
選択・移動時に保存。途中再開可能。書き込み失敗を画面で告知。
リプレイは消去しない。「全初期化」をユーザーが確認した場合だけ両キーを消去。

## PWA

各CSS/JSの参照へ版クエリーを追加して旧キャッシュと新HTMLの混在を抑える。
Service Workerの新キャッシュ名には公開スコープを含め、他ゲームのキャッシュを削除しない。
旧版のスコープなしキャッシュは他サイトとの共有可能性を排除できないため自動削除しない。
必須ファイルの取得が失敗した場合、新Workerのインストールを完了しない。
新Workerの即時反映は明示操作のみ。未完了の試行が再読み込みで失われることを確認文に表示。

## 同一仕様を守る修正

送信待ちにステージを変えた場合、旧セッションの応答が新ステージへ書き込まれないよう破棄する。
日本語IMEの変換確定Enterを送信にしない。
高さの小さいNODE画面ではプロフィールを畳み、質問・送信・ヒント操作を残す。

## 残る制約

ターゲットとNODEはルールベース。語句パターンで突破できる性質は本更新では変更しない。
NPC台詞の自然さは定義済み会話の範囲に限られ、外部AIを使用したと表示しない。
`docs/QA.md`等の旧資料は旧版の記録であり、現行QAは`QA_v1.3.1.md`を参照する。
